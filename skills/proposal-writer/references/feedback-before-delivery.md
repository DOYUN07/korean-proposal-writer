# 최종 파일 출력 전 보완 제안과 피드백


## 기본 흐름
현재 자료와 기존 작성 기준으로 본문 초안을 준비하고, 결과를 바꿀 만한 보완점을 사용자와 논의한 뒤 최종 파일을 생성·검증·전달한다. 피드백용으로 전체 파일을 먼저 완성할 필요는 없다. 현재 초안의 핵심 방향이나 관련 문단을 보여 주어 사용자가 구체적인 안을 판단하게 한다.

## 보완점 선택
공고·양식·평가기준과 초안을 대조하여 누락, 논리적 비약, 약한 근거, 고객의 선택 이유, 실행 가능성, 일정·인력·예산·성과의 연결 중 결과에 영향을 주는 항목을 고른다. 계획서는 실행·지속 운영뿐 아니라 차별성과 평가 대응을, 제안서는 설득뿐 아니라 수행·비용·운영의 현실성을 처음부터 함께 고려한다. 이를 별도 플러그인을 실행해야만 할 수 있는 작업으로 설명하지 않는다.

이미 자료에 있거나 대화에서 결정된 내용은 다시 묻지 않는다. 원문에서 답을 찾을 수 있는 공고 조건은 먼저 확인한다. 조사·계산·오탈자 수정처럼 스스로 해결할 수 있는 작업은 직접 수행한다.

## 제안과 질문 제시
한 번에 우선순위가 높은 질문을 최대 3개로 묶고 각 질문에 다음을 연결한다.
- 현재 초안의 약한 부분과 관련 항목
- 보완하면 좋아지는 이유와 평가·실행상 영향
- 현재 자료에 근거한 추천안과 필요한 경우 선택지
- 사용자가 확인할 사실 또는 선택할 방향

필요하면 해당 문단의 수정 전후 예시나 짧은 작성안을 보여 준다. “추가 자료가 있나요?”처럼 범위 없는 질문만 나열하거나, 회사의 모든 자료를 확보할 때까지 집필을 미루지 않는다. 사실 확인 질문과 전략·범위·표현 선택 질문을 구분한다. 추천안의 장점뿐 아니라 중요한 비용·범위·일정 변화도 함께 밝힌다.

예: “실증 장소만 있고 운영조건 검증이 부족합니다. 품종 변경과 장애 복구를 포함하면 현장 적용성을 설명할 수 있습니다. 방호 셀 시험 후 현장 연속운전으로 확대하는 안을 권합니다. 실증기관이 정해졌나요? 미정이면 기관 선정 조건과 확보 일정으로 작성할까요?”

## 답변 대기와 반영
제시한 질문의 답변을 기다리는 동안 답변과 무관한 조사·집필·검토는 계속한다. 사용자 응답이 없다는 이유만으로 추천안이 승인된 것으로 취급하거나 피드백이 끝났다고 보고하지 않는다. 질문 답변을 기다리는 단계에서는 최종 DOCX 전달을 보류하고, 준비한 내용과 필요한 결정이 무엇인지 짧게 남긴다.

답변을 받으면 수정할 항목과 관련 본문·수치·일정·예산·목표·요약서를 함께 갱신한다. 중요한 변경과 남은 확인사항을 간략히 알린 뒤 기존 내용 검토와 파일·서식 검증을 수행하고 결과물을 전달한다. 피드백 단계의 질문·추천 설명을 제출 본문에 그대로 넣지 않는다.

첫 피드백을 반영하면 원칙적으로 출력으로 진행한다. 이미 정한 내용을 반복 확인하지 않는다. 답변으로 새롭게 드러난 중요한 충돌이나 판단이 필요한 경우에만 추가 질문을 한다. 사소한 문장 개선으로 질문을 반복하거나 파일마다 별도의 출력 허가를 요구하지 않는다.

## 적용 범위와 빠른 작성
전체 초안 또는 내용에 영향을 주는 보강·수정에 적용한다. 간단한 상담·정해진 한두 문장 수정·서식 수정에는 별도 피드백 단계를 강제하지 않는다. 실질적인 보완점이나 사용자 판단이 필요한 항목이 없다면 질문을 만들기 위해 질문하지 말고 검토 후 전달한다.

사용자가 “질문 없이 바로 작성”, “추천안대로 진행”, “알아서 작성”, “현재 정보로 출력”처럼 방향을 정하면 해당 범위의 피드백 단계를 생략하거나 마친 것으로 보고 진행한다. 같은 결정을 다시 확인하지 않는다. 가상 예시가 허용되어도 품질에 영향을 주는 선택은 기본 피드백 대상이며, 질문 생략 지시가 있으면 일관된 가상 설정으로 작성한다.

빠른 작성이나 추천안 적용을 허용받아도 미확인 실적·인증·계약 등 회사 사실과 실제 공고 조건을 창작하지 않는다. 결정되지 않은 중요 사실은 확인 대상으로 남기거나 해당 사실 없이 성립하는 초안을 작성한다. 결과물은 실제 확인 수준에 맞는 검토본으로 전달한다.
